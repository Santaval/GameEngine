# Town tileset (issue #55)

One 16x16 tileset for the town, **generated by code** (no hand-drawn PNG): `tilesets/town.png` +
`tilesets/town.tsx`. It covers lastre, asphalt, zacate, barbed-wire fences, coffee, plantain,
guanacaste, power poles, gutters and the river bank. It is a first pass: the shapes are simple on
purpose and the project owner may redraw any tile later (see "Replacing art" below).

Files:

| File | What |
| --- | --- |
| `tilesets/town.png` | 256x144 sheet, 16 columns x 9 rows, no margin. **Generated, never edit by hand.** |
| `tilesets/town.tsx` | Tiled tileset with the properties of every tile. **Generated.** |
| `tilesets/CREDITS.md` | Credits and licence notes |
| `maps/tiles_demo.tmx` | 40x30 proof map built only from this tileset. **Generated.** Open it with key `8` in the main scene, or in Tiled. |
| `tools/tilegen/` | The generator (Node, no npm packages). `catalog*.mjs` is the single source of truth |

Regenerate with `make tiles` (same as `node games/quebrada/tools/tilegen/gen.mjs`). `make test` runs
`gen.mjs --check`, which fails if the committed files differ from what the code produces, and
`tests/tileset_check.lua`, which validates the properties below.

Preview pictures (not committed): `node games/quebrada/tools/tilegen/gen.mjs --preview <dir>` writes
`sheet_x4.png`, `demo_map.png` and `demo_map_night.png` (the map darkened, to check readability at night).

## Tile ids

`id = row * 16 + col`, ids start at 0 in the `.tsx`; in a map the gid is `id + firstgid` (`firstgid=1`).
Ids not listed are reserved (transparent, no properties). Tile properties:

| Property | Type | Meaning |
| --- | --- | --- |
| `name` | string | Unique name, used by the generator, the demo map and the test |
| `layer` | string | Authoring hint: which tile layer the tile belongs in (see "Layers") |
| `surface` | string | Footstep material: `zacate`, `lastre`, `madera`, `concreto` (see [audio.md](audio.md)) |
| `solid` | bool | Blocks the player (`load_tmx_colliders` reads it) |
| `sort_offset` | int | Added to the Y used to sort the tile with sprites; trunks use `-2` |

Rows: 0 grass, soil, planks, mud | 1 lastre road (fills, ruts, edges, outer and inner corners) |
2 asphalt (lines, crosswalks, manhole) | 3 sidewalk, pavers, gutters, drain, asphalt-to-lastre seams |
4 river water and banks | 5 fences, chain-link, hedge | 6-7 canopies (above) | 8 trunks, bushes, props, overlays.

Edge naming: `lastre_edge_n` has grass on its **north** side. `lastre_outer_nw` has grass on N and W
(a convex lastre corner). `lastre_inner_nw` is full lastre with a grass notch in the NW corner
(the diagonal neighbour is grass). `bank_e` is a land tile with the water to its **east**.

Trees are made of cells: a **3x2 canopy** (`*_canopy_<cx>_<cy>`, layer `above`) placed directly over a
**one cell trunk** (`*_trunk` / `platano_stem`, layer `ysort`, solid) under the canopy's middle column.
The pole is a `poste_head_top` + `poste_head_shaft` (above) over `poste_base` (ysort, solid);
`power_wire` (above) at the same row as the head top continues the cables.

## Layers

The engine only knows `above` and `ysort` as **layer** properties (`engine/docs/lua-api.md`,
"Tile map rendering"), so the tile `layer` property is a hint for whoever builds the map. Use four
tile layers, in this order:

| Layer | Properties | Put there |
| --- | --- | --- |
| `ground` | none | tiles with `layer=ground` (every cell filled; this is where `surface` lives) |
| `overlay` | none | `layer=overlay`: shadows, leaves, puddles (no `surface`) |
| `objects` | `ysort=true` | `layer=ysort`: trunks, fences, posts, bushes, props. The hero walks behind and in front |
| `canopy` | `above=true` | `layer=above`: treetops, pole heads, wires |

Rules the test enforces:

- Every `ground` tile that is not `solid` has a valid `surface`. The footstep code
  (`surface_logic.surface_at`) takes the top-most tile layer that has a `surface` under the foot, so
  `overlay`, `ysort` and `above` tiles must **not** carry one (otherwise a treetop would change the sound).
- `solid` is only on water (ground) and on `ysort` tiles. `load_tmx_colliders` with no options collides
  with **every** tile layer, so no engine change is needed. If you pass the `tile_layers` option, include
  `ground` or the water will not block.
- Canopy cells are `above`; trunks are `ysort` + solid; the `ysort` layer only sorts in scenes that
  load the map with `load_tile_map` (`tile_map = true`, below).

## Using it in a scene

`town_controller.make_update{ map = "maps/tiles_demo.tmx", tile_map = true }` calls `load_tile_map(map)`
before `load_tmx_colliders`. Without `tile_map` the controller keeps drawing nothing for tile layers
(as `town.tmx`, which has object layers only). `scenes/tiles_demo.lua` + `scripts/tiles_scene.lua` show it.

## Add or change a tile

1. Edit the right `catalog_*.mjs` (ground, fences, plants). A single tile is
   `add(row, col, name, props, draw)`; a multi-cell object is an entry in `plantTiles.objects()` that
   draws on one canvas and lists its cells.
2. Each tile gets its own random seed from `hash(GLOBAL_SEED, name)`, so changing one tile does not move
   the pixels of the others. Material textures (`materials.mjs`) depend only on position, so edge
   tiles stay seamless with the fills.
3. `make tiles`, then `--preview` and look at the sheet and the demo map (and the night copy).
4. Add the name to `REQUIRED` in `tests/tileset_check.lua` if the map or the docs depend on it.
5. Commit the regenerated `.png`, `.tsx` and `.tmx`.

Never edit `town.png` by hand: the next `make tiles` overwrites it and `make test` would fail.

## Replacing art

To use hand-drawn art instead, draw a new sheet with the same ids (or extend the layout), keep the
properties of `town.tsx`, and stop running `make tiles`. Remove the `--check` line from the Makefile
and update `tilesets/CREDITS.md`.

## Limits and notes

- Canopy as `above` assumes the 16x16 hero; taller sprites may need the lower canopy cells in `ysort`.
- Buildings and roofs are out of scope (they will come with `roof_of` layers). A later tileset needs its
  own `firstgid`; `tests/tileset_check.lua` already reads `firstgid` from the map and masks flip flags.
- Palette is mid-tone on purpose so the lighting layer's darkening stays readable.
